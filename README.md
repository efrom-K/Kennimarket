# leadgen — прототип сбора холодных лидов на покупку складов (Москва/МО)

Локальный пайплайн: сырые данные из публичных источников -> локальная LLM (через LM Studio)
классифицирует/структурирует -> SQLite -> CSV-выгрузка.

## Почему именно эти источники

- **Avito / Cian / list-org.com / rusprofile.ru / zachestnyibiznes.ru — сознательно НЕ используются.**
  Avito и Cian прямо запрещают автосбор в ToS, а телефон физлица-продавца — персональные данные
  по 152-ФЗ. list-org.com и rusprofile.ru явно блокируют `/search` в robots.txt (rusprofile
  дополнительно поимённо блокирует ClaudeBot), zachestnyibiznes.ru стоит за DDoS-Guard.
- **Telegram (публичные чаты и каналы о коммерческой недвижимости)** — реальный сигнал покупательского
  намерения ("куплю склад", "ищу клиенту склад на покупку"), собирается через официальный Telegram API.
  Запросы покупателей пишут в основном в **группах** (чаты брокеров/объявлений), каналы — в основном продавцы и новости.
- **2GIS Catalog API** — компании сами публикуют телефон, чтобы им звонили; официальный API,
  а не скрейпинг HTML. Даёт объём (firmographic target-list: опт/логистика/производство в МО),
  которого не даст точечный intent-сигнал из Telegram.

## Установка

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # и заполнить ключи, см. ниже
```

### 1. LM Studio
Открой LM Studio -> вкладка **Developer / Local Server** -> Start Server (по умолчанию
`http://localhost:1234`). Модель — `qwen3-4b-instruct-2507` (в `.env` уже проставлена).

Выбрана замером на 48 вручную размеченных сообщениях из реальных чатов (Mac M2, 8 ГБ RAM):

| Модель | Точность | Полнота | Скорость |
|---|---|---|---|
| `qwen2.5-3b-instruct` (старый промпт) | 0.92 | 0.71 | 3 с/сообщ. |
| `qwen3-4b-instruct-2507` (старый промпт) | 0.82 | 1.00 | 6 с/сообщ. |
| **`qwen3-4b-instruct-2507` (текущий промпт)** | **0.94** | **0.94** | ~9 с/сообщ. |
| `prism-ml/bonsai-27b` (5.2 ГБ) | — | — | не влезает: своп, 20+ мин без результата |

Промпт задаёт модели три отдельных вопроса (`wants_to_buy`, `object_fits`, `other_region`), решение
"лид или нет" принимается в коде (`pipeline.is_telegram_lead`) — на прямые вопросы маленькая модель
отвечает заметно надёжнее, чем через один общий `confidence`. Reasoning-модели (deepseek-r1) и 9B
на 8 ГБ не годятся: медленно и/или своп. На машине с 16+ ГБ можно пробовать 7–14B — просто поменяй
`LM_STUDIO_MODEL` (и `LM_STUDIO_BASE_URL`, если LM Studio на другой машине в LAN).

### 2. Telegram API
Зайди на https://my.telegram.org -> API development tools, создай приложение (номер телефона,
код из SMS). Впиши `TELEGRAM_API_ID` и `TELEGRAM_API_HASH` в `.env`. При первом запуске команды
`telegram` попросит интерактивно ввести номер телефона и код — это создаст файл сессии
(`leadgen_session.session`), дальше логин не требуется.

### 3. 2GIS Catalog API
Зарегистрируйся на https://dev.2gis.ru/ и получи бесплатный ключ. Впиши в `DGIS_API_KEY`.
**Важно:** названия полей ответа (`contact_groups`, `rubrics`, `address_name`) в `leadgen/sources/dgis_source.py`
взяты по документации API — из этого окружения у меня не было доступа к живому 2GIS API, чтобы
свозить реальный ответ, так что при первом запуске сверь структуру JSON-ответа с кодом (если
не распарсится телефон — открой `raw_items` в БД и проверь `raw_text`/добавь `print(item)` в цикл).

## Приложение

**Установка на Mac (один раз):** `macos/build_app.sh` — соберёт `Kennimarket.app` и положит в «Программы».
Дальше запуск из Launchpad / Dock. Веб-версия: двойной клик по `Kennimarket.command` (или `streamlit run app.py`),
откроется в браузере на http://localhost:8501.

Модель запускается сама: при старте приложения (и веб-версии) LM Studio поднимает сервер и
загружает `qwen3-4b-instruct-2507` через свой CLI `lms` — открывать LM Studio вручную не нужно,
нужно только, чтобы она была установлена и модель скачана. Если LM Studio во время сбора выгрузит
модель, сбор сам загрузит её обратно. В боковой панели есть кнопка «Запустить модель» на всякий случай.
Вход в Telegram — один раз в терминале: `python3 cli.py telegram --channels mossdelka` (номер + код).
Состояние модели и Telegram видно внизу боковой панели (зелёная точка — всё ок).

- **Сбор** — «Запустить сбор»: ищет запросы в чатах (по умолчанию только группы, за 90 дней), идёт в фоне,
  окно можно закрыть. «Найти новые чаты» — пополняет список чатов.
- **Лиды** — свежие сверху. «Написать» открывает диалог в Telegram, «Сообщение» — исходный пост,
  статус меняется прямо в карточке, комментарий — в «Детали». Таблица и CSV — для выгрузки.
- **Обзор** — сколько лидов, откуда, на каком этапе.
- **Чаты** — галочкой включить/выключить чат, «Добавить чат» по ссылке.
- **Объекты** — ваши готовые склады на продажу: «Скачать шаблон» (Excel), заполнить, загрузить.
  Под них подбираются лиды и пишутся первые сообщения.
- **Настройки** — агентство, имя менеджера, телефон: так вы представляетесь в сообщении.

**Первое сообщение.** Для каждого нового лида модель разбирает запрос (тип, площадь, направления,
бюджет), код подбирает ваш готовый склад и собирает живой текст: представиться, одна фраза про их
запрос, объект, предложение презентации и просьба оставить номер, если его нет. Цифры — только из
базы объектов. Нет подходящего склада — черновика нет (в карточке причина и выбор объекта вручную).
В карточке: правка текста → «Открыть чат с текстом» (в приложении для Mac текст ещё и в буфере обмена)
→ отправить в Telegram → «Отправил». Для старых лидов — «Подготовить» на странице «Сбор».

## Запуск (командная строка)

```bash
source .venv/bin/activate

# Инициализация БД (leadgen.db, путь настраивается в .env)
python3 cli.py init-db

# Найти публичные чаты/каналы (поиск Telegram + раскрутка через «похожие каналы») -> channels.txt
python3 cli.py tg-discover --depth 2
# Серверный поиск buy-intent по всей истории каждого чата из списка (группы идут первыми)
python3 cli.py telegram --channels-file channels.txt
# или точечно: python3 cli.py telegram --channels "kommercheskay,mossdelka"

# Сбор компаний-таргетов через 2GIS
python3 cli.py dgis --pages 10

# Статистика по собранным лидам
python3 cli.py stats

# Выгрузка в CSV
python3 cli.py export --out leads.csv
```

Обе команды (`telegram`, `dgis`) идемпотентны и докручиваются: уже виденные `raw_items`
(по `source`+`source_id`) не обрабатываются повторно, а лиды дедуплицируются по телефону/email/
telegram-юзернейму/названию компании — можно запускать многократно, добавляя новые каналы/запросы,
пока `stats` не покажет нужные ~1000 (`TARGET_LEADS` в `.env`).

## Структура

```
cli.py                       # точка входа (argparse)
leadgen/
  config.py                  # настройки из .env
  db.py                      # SQLite: raw_items + leads, дедуп
  llm.py                     # клиент LM Studio (OpenAI-совместимый /v1/chat/completions)
                              # + устойчивый парсинг JSON из ответа модели
  pipeline.py                # оркестрация: источник -> LLM-классификация -> запись в БД
  sources/
    telegram_source.py       # Telethon: поиск чатов, серверный поиск по истории, regex-префильтр
    dgis_source.py           # 2GIS Catalog API
```

## Что осознанно не сделано (вне рамок прототипа)

- Обход анти-бот защиты Avito/Cian/zachestnyibiznes.ru.
- Автоматический сбор телефонов физлиц без правового основания (152-ФЗ).
- Продакшен-надёжность: ретраи с backoff, ротация прокси, мониторинг, масштабирование очереди.
- Верификация/санитайзинг телефонов (нормализация в E.164) — сейчас телефон хранится как есть.

## Что проверено в этой сессии, а что нет

Проверено вживую: инициализация БД, вставка/дедуп лидов, парсинг "грязного" JSON (markdown-обёртка,
висячая запятая, `<think>`-блок reasoning-моделей); реальные вызовы `LMStudioClient` к настоящему
LM Studio-серверу на трёх моделях (см. раздел про LM Studio выше) — итоговая связка
`qwen2.5-3b-instruct` верно классифицировала все тестовые сообщения (покупка/аренда/неявная покупка)
с корректным извлечением company_name/contact_name/phone/location/area_sqm/budget.

Не проверено вживую (нужна твоя реальная среда): реальный ответ 2GIS Catalog API (сеть до 2gis.ru
была недоступна из sandbox-окружения, где писался код — при первом запуске сверь структуру JSON-ответа
с кодом в `dgis_source.py`), Telegram-логин и реальные сообщения из конкретных каналов (нужен
интерактивный ввод кода из SMS + список реальных каналов, которых у меня нет).
