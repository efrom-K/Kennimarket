# leadgen — прототип сбора холодных лидов на покупку складов (Москва/МО)

Локальный пайплайн: сырые данные из публичных источников -> локальная LLM (через LM Studio)
классифицирует/структурирует -> SQLite -> CSV-выгрузка.

## Почему именно эти источники

- **Avito / Cian / list-org.com / rusprofile.ru / zachestnyibiznes.ru — сознательно НЕ используются.**
  Avito и Cian прямо запрещают автосбор в ToS, а телефон физлица-продавца — персональные данные
  по 152-ФЗ. list-org.com и rusprofile.ru явно блокируют `/search` в robots.txt (rusprofile
  дополнительно поимённо блокирует ClaudeBot), zachestnyibiznes.ru стоит за DDoS-Guard.
- **Telegram (публичные каналы о коммерческой недвижимости)** — реальный сигнал покупательского
  намерения ("куплю склад", "ищу склад в собственность"), собирается через официальный Telegram API.
- **2GIS Catalog API** — компании сами публикуют телефон, чтобы им звонили; официальный API,
  а не скрейпинг HTML. Даёт объём (firmographic target-list: опт/логистика/производство в МО),
  которого не даст точечный intent-сигнал из Telegram.

## Установка

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # и заполнить ключи, см. ниже
```

### 1. LM Studio
Открой LM Studio -> вкладка **Developer / Local Server** -> Start Server (по умолчанию
`http://localhost:1234`). Модель — `qwen2.5-3b-instruct` (в `.env` уже проставлена).

Это не случайный выбор — по факту протестировано в этой же сессии на реальной машине (Mac,
8 ГБ RAM, без дискретной GPU):
- `deepseek-r1-0528-qwen3-8b` (reasoning-модель) — 55 сек/запрос, тратит ~80% токенов на
  `<think>`-рассуждение и в итоге **неправильно** классифицировала однозначный buy-intent текст
  как нерелевантный. Не годится для этой задачи вообще, независимо от размера машины.
- `qwen3.5-9b` и `ornith-1.5-9b-mlx` (9B) — либо не грузятся ("insufficient system resources"),
  либо грузятся, но резко проседают по скорости (своп) на 8 ГБ RAM.
- `qwen2.5-3b-instruct` (1.75 GB, MLX, 4-бит) — 2-5 сек/запрос, верно распознала все 3 тестовых
  случая (покупка/аренда/неявная покупка) с корректным извлечением полей. На 8 ГБ RAM — оптимум.

Если поднимешь пайплайн на машине с RTX 3060 (или другой GPU с 8-12 ГБ VRAM) — там комфортно
пойдёт модель 7-14B (например `qwen2.5-14b-instruct`), это даст более тонкую классификацию
неоднозначных сообщений. Тогда просто поменяй `LM_STUDIO_BASE_URL` на `http://<ip-той-машины>:1234/v1`
(не забудь включить приём соединений по LAN в настройках LM Studio Server) и `LM_STUDIO_MODEL`.

### 2. Telegram API
Зайди на https://my.telegram.org -> API development tools, создай приложение (номер телефона,
код из SMS). Впиши `TELEGRAM_API_ID` и `TELEGRAM_API_HASH` в `.env`. При первом запуске команды
`telegram` попросит интерактивно ввести номер телефона и код — это создаст файл сессии
(`leadgen_session.session`), дальше логин не требуется.

### 3. 2GIS Catalog API
Зарегистрируйся на https://dev.2gis.ru/ и получи бесплатный ключ. Впиши в `DGIS_API_KEY`.
**Важно:** названия полей ответа (`contact_groups`, `rubrics`, `address_name`) в `leadgen/sources/dgis_source.py`
взяты по документации API — из этого окружения у меня не было доступа к живому 2GIS API, чтобы
свозить реальный ответ, так что при первом запуске сверь структуру JSON-ответа с кодом (если
не распарсится телефон — открой `raw_items` в БД и проверь `raw_text`/добавь `print(item)` в цикл).

## Запуск

```bash
source .venv/bin/activate

# Инициализация БД (leadgen.db, путь настраивается в .env)
python3 cli.py init-db

# Скан Telegram-каналов на buy-intent (список каналов подставь свой)
python3 cli.py telegram --channels "cre_moscow,sklad_msk,realty_msk" --limit 1000

# Сбор компаний-таргетов через 2GIS
python3 cli.py dgis --pages 10

# Статистика по собранным лидам
python3 cli.py stats

# Выгрузка в CSV
python3 cli.py export --out leads.csv
```

Обе команды (`telegram`, `dgis`) идемпотентны и докручиваются: уже виденные `raw_items`
(по `source`+`source_id`) не обрабатываются повторно, а лиды дедуплицируются по телефону/email/
telegram-юзернейму/названию компании — можно запускать многократно, добавляя новые каналы/запросы,
пока `stats` не покажет нужные ~1000 (`TARGET_LEADS` в `.env`).

## Структура

```
cli.py                       # точка входа (argparse)
leadgen/
  config.py                  # настройки из .env
  db.py                      # SQLite: raw_items + leads, дедуп
  llm.py                     # клиент LM Studio (OpenAI-совместимый /v1/chat/completions)
                              # + устойчивый парсинг JSON из ответа модели
  pipeline.py                # оркестрация: источник -> LLM-классификация -> запись в БД
  sources/
    telegram_source.py       # публичные каналы через Telethon + keyword-префильтр
    dgis_source.py           # 2GIS Catalog API
```

## Что осознанно не сделано (вне рамок прототипа)

- Обход анти-бот защиты Avito/Cian/zachestnyibiznes.ru.
- Автоматический сбор телефонов физлиц без правового основания (152-ФЗ).
- Продакшен-надёжность: ретраи с backoff, ротация прокси, мониторинг, масштабирование очереди.
- Верификация/санитайзинг телефонов (нормализация в E.164) — сейчас телефон хранится как есть.

## Что проверено в этой сессии, а что нет

Проверено вживую: инициализация БД, вставка/дедуп лидов, парсинг "грязного" JSON (markdown-обёртка,
висячая запятая, `<think>`-блок reasoning-моделей); реальные вызовы `LMStudioClient` к настоящему
LM Studio-серверу на трёх моделях (см. раздел про LM Studio выше) — итоговая связка
`qwen2.5-3b-instruct` верно классифицировала все тестовые сообщения (покупка/аренда/неявная покупка)
с корректным извлечением company_name/contact_name/phone/location/area_sqm/budget.

Не проверено вживую (нужна твоя реальная среда): реальный ответ 2GIS Catalog API (сеть до 2gis.ru
была недоступна из sandbox-окружения, где писался код — при первом запуске сверь структуру JSON-ответа
с кодом в `dgis_source.py`), Telegram-логин и реальные сообщения из конкретных каналов (нужен
интерактивный ввод кода из SMS + список реальных каналов, которых у меня нет).
